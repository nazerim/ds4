The vocabulary and merge loops (`ds4.c:65040-65045`, `ds4.c:65053-65059`) hash tokenizer data. They won't catch a code-only change to pre-tokenization when those tables stay the same. The probes run the rendered-chat tokenizer (`ds4.c:45939`, `ds4.c:65060-65067`) and hash the resulting token IDs, so they can catch code changes that affect those inputs.

The list was hand-picked to exercise JoyAI cases like apostrophes next to punctuation, digit runs, indentation, newlines, and UTF-8 text (`ds4.c:65002-65018`). If a tokenizer fix changes behavior the current inputs don't cover, append a small example rather than editing or reordering the existing entries. Appending a probe that produces tokens changes the fingerprint even if the old probes still produce the same IDs.
