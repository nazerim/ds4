The vocabulary and merge loops (`ds4.c:65040-65045`, `ds4.c:65053-65059`) hash tokenizer data. They won't catch a code-only change to pre-tokenization when those tables stay the same. The probes run the rendered-chat tokenizer (`ds4.c:45939`) and hash the resulting token IDs (`ds4.c:65060-65067`), so they are the part that can catch such a change.

The list was chosen to exercise JoyAI pre-tokenizer cases: apostrophes next to punctuation, digit runs, indentation, newlines, UTF-8 text (`ds4.c:65002-65018`). It needs updating when a tokenizer fix changes behaviour those inputs don't cover. Any change to the list moves the fingerprint, appending included, so the cost is the same either way: existing stamped checkpoints miss once and are re-prefilled.
