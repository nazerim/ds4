Yes: the fingerprint includes the vocabulary size, every token in ID order and the merge table (`ds4.c:65039-65059`), so appending even an unused token changes it. A mismatch makes `ds4_kvstore_try_load_text` return a miss without deleting the file (`ds4_kvstore.c:1307-1317`).

One gap in the store path: `kv_cache_existing_compatible` (`ds4_kvstore.c:849-870`) doesn't compare the stamp, so a same-text file that passes the other checks goes to `kv_cache_rewrite_trailer` (`ds4_kvstore.c:889-930`, called at `ds4_kvstore.c:1003`). That rewrites the trailer with the current fingerprint and keeps the old KV payload. The pre-check comment says the ordinary prefill path "rewrites a fresh stamped file under the same text key" (`ds4_kvstore.c:1280-1288`), but at this head it doesn't.
