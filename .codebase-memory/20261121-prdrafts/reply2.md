Yes, even an unused token added at the end of the vocabulary changes the fingerprint: it includes the vocabulary size, every token in ID order, and the merge table (`ds4.c:65039-65059`). That's a conservative trade-off. An append can leave existing tokenization unchanged, but this PR doesn't try to establish that it's safe to reuse the old checkpoint. If the loader reads a valid stamp and it doesn't match, it returns a cache miss without deleting the file (`ds4_kvstore.c:1307-1317`).

There's a store-side gap in this PR: if the same-text file passes the other compatibility checks, the store path can rewrite its trailer with the current stamp without replacing the old KV payload (`ds4_kvstore.c:1003-1010`). I have a separate fix that checks the stamp before allowing reuse; it's not part of this PR.
