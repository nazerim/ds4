## Concrete lead found at handover time (verify first!)

`qwen4_gemv_rows` (ds4.c:~58200): the dense-mm F16 arm is gated
`f16_batch = n_tok > 3u && n_tok <= 64u && (out_dim <= 512u || n_tok > 8u)`.
**An 8192-row prefill chunk never satisfies n_tok <= 64** → every F16
projection (qkv/o? gdn in-proj/z/ga/beta, hc down/up, conv-gate inputs...)
runs the custom `ds4_gpu_matmul_f16_tensor` at prefill. The model-free bench
(QWEN4_BENCH=1, `--- prefill T=256 ---`) says the arms split by SHAPE:
- hc down f16 320x10240 T=256: custom 417 us vs dense-mm **272** (mm 1.5x faster)
- hc up f16 10240x320 T=256: custom **69** vs dense-mm 208 (custom 3x faster)
- router f32 512x2560: custom 727 vs **142** mm — f32>8-row already routes mm
  in the live path (the (n_tok>8 && F32) clause) → mm win IS taken; the bench
  custom arm is only an upper-bound marker. Same for F16 IF the cap allowed.
GDN bucket (1.5s/chunk) is mostly projections + scan (scan itself ~0.33s
of it), so the same arm choice gates it. MoE experts are q4k/mxfp4 (the
`moe mm 32 experts T=2048 x10 slots = 6643 us` arms) — separate audit leg.
