## TL;DR

- One new kernel, `kernel_qwen4_attn_mm_nax`: the FULL QSA main attention
  (scores → online softmax → P·V → normalize → sigmoid gate) rewritten on
  Metal 4 tensor units (`matmul2d` cooperative tensors, f16 operands, fp32
  accumulators). Port of oMLX's NAX QSA attention (jundot/omlx#4020).
- **Perf: measured e2e prefill +2.8–7.4% (author's host = M5 Max 128 GB —
  same chip class as ours); QSA kernel 1.31x at T=1024/256k sparse, 2.38x
  when selection is in the last 8k.** This is our bucket (attention ≈ 24%
  of live prefill) at our long-context sparse shapes.
- **Numerics: NOT bit-exact on prefill rows (T>8)** — tensor-tree
  accumulation order → ~1 ulp drift (author: max |delta| < 1e-4 random;
  e2e top-1 identical at 8k/32k/64k). Bit-exact everywhere the umbrella
  cares about: T≤8 verify/decode rows and key-split runs keep the classic
  kernel (gate closed; asserted `worst_cls == 0.0` in the new test).
- **The pinned golden battery is insulated by construction**: the golden
  harness forces `DS4_METAL_DISABLE_METAL4=1` (tests/ds4_test.c:6323), so
  NAX never runs under golden capture/verify. **Production is NOT
  insulated** — `ds4-server.sh` sets neither that env nor `--quality`, so on
  this M5 Max host the live prefill stream drifts ~1 ulp the moment a merged
  binary lands. That is exactly the fork's "golden decision" class (same
  class as the HC f16 arm swap we declined).
- This answers our banked QSA-ATTRIBUTION open question: the lever that
  works for main attention is the tensor-unit datapath rewrite, not tile
  geometry (our TM-widen was occupancy-bound; NAX restructures the whole
  kernel: 64 vs 128 threads/group, 32-key steps, cross-simdgroup partials).

## Kernel summary (pr1149:2590-2894)

- Grid: one 64-thread (2-simdgroup) threadgroup per (kv head, token).
- The query's GQA group (≤16 heads) is one 16-row tensor tile; head_dim 256
  split 128/128 across the two simdgroups with partial-score exchange via
  threadgroup memory; key loop walks the query's selection list 32 keys/step
  with software-pipelined fetches.
- QKᵀ and P·V are 16×32×32 `matmul2d` tensor ops; P staged half (same
  rounding as classic); O accumulates in persistent fp32 cooperative
  tensors across the whole key loop.
- Scalar softmax (m/l per row) and the normalize+sigmoid-gate epilogue
  deliberately match the classic kernel's expressions.

## Dispatch (ds4_metal.m +13; no ds4.c changes needed)

- Inside the EXISTING `ds4_gpu_qwen4_attn_decode_tensor` mm gate
  (`n_splits==1 && n_tokens>8 && head_dim==256 && n_head/n_head_kv<=16 &&
  !DS4_QWEN4_NO_ATTN_MM`), NAX runs iff:
  `ds4_gpu_mpp_available()` (Metal4 tensor API: device M5/M6/A19/A20 +
  compile probe; disabled pre-M5) && `DS4_QWEN4_NO_ATTN_MM_NAX` unset &&
  pipeline compiles. Otherwise classic `kernel_qwen4_attn_mm`. `--quality`
  mode and key-split runs also take the classic kernel.
- **Default on our M5 Max production host: NAX ON for prefill attention.**
  Kill switch: `DS4_QWEN4_NO_ATTN_MM_NAX=1`. M3 Ultra: never.
