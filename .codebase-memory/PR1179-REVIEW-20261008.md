## GDN deep-dive (the question we asked)

- `kernel_qwen4_gdn_fused` (qwen4.metal:1223-1325 in pr1179): fuses q/k norm +
  gates + serial r4 scan + out-norm for T<=16, one 1024-thread group per v-head.
  Arithmetic character-identical to the reference kernels (bit-exact by
  construction, `#pragma clang fp reassociate(off)` on the norm loops).
  Host: `ds4_gpu_qwen4_gdn_fused_tensor` (ds4_metal.m:50702), constraints
  n_tokens 1..16, head_dim 128.
- `kernel_qwen4_gdn_front_rows` (:5680): gdn_front over a batch row table
  (batched-session decode). `kernel_qwen4_q8_concat_conv` (:5946) +
  `q8_rows_conv<1..4>` (:6002): qkv/z Q8_0 projection with the causal conv as
  epilogue + alpha/beta row dots — decode-path fusion.
- Scan changes are dispatch-only: `snap_tok` generalized to `snap_rows`
  (multi-slot snapshots, snap_rows==1 behavior-identical); r4 extended from
  T<=3-verify to ALL verify rows T<=16 when `verify_rows_exact` (ds4_metal.m:49021).
- ds4.c call sites (~:58555): T==1 plain decode -> q8_pair_conv + gdn_fused(1)
  (default on M3 Ultra, `DS4_QWEN4_GDN_UNFUSED` kill switch); verify rows
  T in 2..16 -> q8_rows_conv + gdn_fused(T) with replay; prefill T=8192 ->
  UNCHANGED gemv/conv/prep/scan/out path.
