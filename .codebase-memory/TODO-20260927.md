# TODO 2026-09-27 — KV delta stores (P1): append-only chained checkpoints

## Why
Continued-ladder stores rewrite the FULL row blob each grid hit (421 MiB @10k,
3.1 GiB @93k evict, ...). k anchors per lineage ≈ k/2 × final size -> one heavy
day consumed 126 GiB of the 128 GiB budget (5 ENOSPC rejections). Disk has
1.1 TiB free but the quadratic format is the real problem. Decision (2026-09-27):
cache cleared, budget stays 128 GiB, P0 (budget bump) SKIPPED — agents can
regenerate; Qwen3.8 prefill is fast (~1150 t/s).

## Core idea
Rows at position p depend only on (exact token prefix ≤ p, weights, tokenizer,
quant regime) — and quantization is PER-ROW (`dsv4_fp8_kv_quantize_row_inplace_cpu`),
so prefix rows are byte-stable across frontiers. Store a continued-ladder node
as a DELTA: full fixed sections + row bytes ONLY for [parent_frontier, N).
Identity/verification stack already exists — NO new hashes needed:
- filename = SHA-1 of rendered byte prefix (lookup unchanged, even for deltas)
- v2 header: conv_id, model_fp, bucket, level
- EXT_TOKFP behavioral tokenizer fingerprint (refused at load on mismatch)
- payload u32 header self-checks (MAGIC/VERSION/TAG/shape rows<=ctx)
- tokens section kept FULL in every file (4 B/token) -> every delta is
  self-describing and prefix-verifiable against its parent's text section.

## Payload layout (qwen4, ds4.c qwen4_session_save_payload)
fixed:  [u32 header][tokens(full)][logits][mtp_rows u32]
per layer:
  linear layers   : [state][hist]                      FIXED size -> full copy
  attn (non-nextn): [k][v] kv=n*HKV*HD*2, [ik] n*IHFD*4,
                    [block_key] (n/4)*IHFD*2           ROW-scaled -> SLICE [A,N)
  nextn (MTP)     : n = mtp_rows                        P1: full copy (small #layers)
tail:   [ple_hist FIXED][ple_prev FIXED][mrope_delta][pos3 rows*16 -> SLICE]
block_key is grouped by 4 rows -> delta boundary must be %4==0 (grid is 2048-mult ✓).

## Format v3 (file header, ds4_kvstore.c)
version byte 3; append: raw parent SHA-1 (20 B) + u32 delta_from_rows.
chain semantics: node covers rows [delta_from, tokens); parent file covers
[.., delta_from). Full nodes: delta_from=0, parent_sha=0 (loader same path).

## Design decisions
- SCOPE: qwen4 local sessions ONLY (the 128G pressure). ds41/deepseek/cpu/TP/
  distributed keep full format untouched.
- Ladder only: reason=continued gets delta; cold/evict/divergence/shutdown stay
  full (they're the chain roots). No DAG delta-chains until P2.
- Parent selection: kvstore keeps last-written anchor per conversation
  (sha, tokens, text_len; process-lifetime, seeded also from a successful LOAD).
  Store N: delta if parent exists, tokens<N, N%4==0, parent file present, and
  parent TEXT is a byte-prefix of this text (verify from text cache or file).
  Any miss -> write full, reset record. Self-healing by construction.
- Load stitch: hit file v3 -> walk parent_sha to path (dir convention), verify
  per link (parent.tokens==child.delta_from, parent.text prefix of child,
  conv/regime match); read files ROOT->CHILD with (A=own delta_from): fixed
  sections overwrite (last=child wins), row slices fill tensors at offset A.
  Any link broken -> fallback: nearest intact ancestor usable OR discard and
  recompute (existing fail-safe semantics, loud log).
- mtp_rows span: always [0, mtp_rows) per file (P1) — nextn layers few and
  small; P2 may slice.
- Refcount: in-memory parent-child map (rebuilt by header scan at open).
  Redundant/bucket eviction SKIPS files with live children (deferred to when
  children die). P2 = full middle-retire GC + re-anchor rewrite.
- Kill switch: DS4_KV_DELTA=0 disables (full stores, old behavior). Ship P1
  default ON after live verification passes; env still honored.
- Telemetry: extend "kv cache stored" line with `delta=<from>..<to>` when v3.
